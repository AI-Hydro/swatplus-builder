# Surrogate calibration research

Research date: 2026-10-02. Scope: primary papers and official software; no engine runs, package installation or production changes. Recommendations are hypotheses to benchmark, not demonstrated improvements in Builder.

## Recommendation

Test **single-region constrained Gaussian-process optimization** as a challenger to DDS, retaining DDS as the reference. Use the same governed parameter bounds, training period, locked simulator, budget ledger and independent verification. Start serially; add small batches only after candidate execution is isolated and auditable. Do not copy the standard TuRBO initialization or create many trust regions under a 30-call search budget. The promising ambitious strategy is **failure-aware, process-constrained, asynchronous surrogate optimization with adaptive parameter groups and selective high-fidelity verification**. Its potential scientific contribution is measured savings in engine calls needed to reach independently verified admissible calibration, including failure costs and cross-basin heterogeneity—not simply applying Bayesian optimization to SWAT+.

RBF-DYCORS is a valuable second surrogate comparator, particularly at larger budgets or when compatible screening provides an adequately spanning initial design. A random-forest surrogate is a robustness comparator when the objective is discontinuous, but should not be treated as a default improvement without testing its uncertainty and constraint behavior.

## Fit to the current implementation

The inspected `src/swatplus_builder/calibration/locked_benchmark.py` implements `_dds_search`, four default diagnostic phases and `_score_candidate`. Phase groups overlap. The final phase considers all retained parameters; the earlier volume, subsurface and timing groups have smaller dimensions. The DDS search has separate score and feasibility callbacks, but its internal walk assigns discontinuous ranks to feasibility states. `_score_candidate` may return negative infinity on failed process gates and mixes raw KGE, NSE and log-KGE. These are not safe targets for an ordinary GP fit without an explicit observation representation.

The working task's approximate setting is 14 retained dimensions and 30 search calls plus screening. Actual retained dimensionality, full phase budgets and call totals must be read from each run ledger before benchmarking. A nominal budget should never conceal screening, baseline calls, anchors, failed attempts, verification or repeated carried-forward seeds.

Changing the optimizer cannot repair an invalid low-flow metric, non-finite ET, forcing bias or unsupported parameter controls. The paper's unit-scaling counterexample remains a prerequisite issue: freeze a scientifically justified objective version before comparing optimization methods. Separate an optimizer-only benchmark using the same finite existing score from a separately labeled objective-redesign experiment; do not attribute objective changes to the optimizer.

## Practical challenger: small-budget constrained GP

1. Normalize parameters to a unit cube using governed bounds; retain any transformations and write-through semantics in provenance. Use CPU double precision. Start with a regularized Matérn GP and conservative hyperparameter priors; at very small sample sizes use a shared lengthscale or shrinkage rather than trying to infer 14 unconstrained lengthscales reliably.
2. Import already evaluated baseline and screening candidates only if their full parameter vectors, engine/input hashes, scoring dates, output scope and objective definition match. Recompute phase utilities from retained raw metrics where valid. Unrecorded parameter values or different simulation periods prohibit reuse. One-dimensional screening points are useful observations but do not identify all interactions.
3. Under a genuinely cold 30-call budget, predeclare a small design, for example 8–10 total baseline/design observations followed by adaptive suggestions. This is a test setting, not a guaranteed sufficient design for 14 dimensions. Shared design costs must be charged identically in all arms. Avoid separate initialization for every phase.
4. Use a single trust region centered on the best admissible candidate, or the least violating candidate while none is admissible. Retain some predeclared global exploration so a misleading incumbent does not absorb the entire budget. Compare a GP with constrained log expected improvement against constrained Thompson sampling at a larger budget; do not inflate the first trial with many acquisition variants.
5. Return the best **actually simulated** admissible candidate. Predictions may guide requests; they cannot authorize promotion. Run the current independent full verification and unchanged claim gates.

Required optional dependency group: pinned PyTorch, GPyTorch and BoTorch; no GPU is needed for tens to hundreds of samples. An ask/tell backend should receive immutable candidate observations and remain independent of simulator execution. Budget, random state, GP state/hyperparameters, trust-region history, pending points and the selected acquisition must be checkpointed.

## Objective, constraints and failed runs

Model finite utility separately from continuous constraint residuals. For the existing volume policy, one example is `g_volume = abs(PBIAS)/30 - 1`, with feasibility at or below zero. Use the exact current process formulas and thresholds for other residuals; distinguish genuine conservation quantities from configured plausibility rules. Input/engine provenance is a deterministic prerequisite, not a tunable scientific constraint. Missing tests are unavailable, not passing.

The official BoTorch constraints guide distinguishes input constraints from modeled output constraints. A probability of feasibility is part of candidate selection and never a substitute for the observed gate. [Official constraints guide](https://botorch.org/docs/next/constraints).

A crash, timeout, NaN or malformed output cannot become a synthetic utility of `-1e6` and enter a GP as a physical observation. Record execution status and failure kind; fit utility and numeric constraint models only where those measurements exist. Learn numerical admissibility with a separate classifier only after enough positive and negative examples exist; with a tiny dataset use conservative rules, region avoidance and fallback exploration. Authentication/provider failures are infrastructure events, not evidence that a parameter region is hydrologically inadmissible. All attempted executions still count in elapsed time and attempted-call accounting.

For RBF-DYCORS, the default cubic RBF has a linear polynomial tail. The official implementation requires at least the tail dimension's number of observations, and nonsingular fitting also needs adequate design rank. At 14 variables the linear tail has 15 coefficients; fewer than 15 suitably spanning samples cannot initialize that default fit. Screening may supply rank, but check it explicitly and remove duplicate full vectors. [Official RBF source](https://github.com/dme65/pySOT/blob/master/pySOT/surrogate/rbf.py). Smaller phase-specific models are possible, provided other parameters are fixed or explicitly represented; projecting changing full vectors onto a small group would create inconsistent training labels.

## Ambitious research strategy

Develop an asynchronous constrained optimizer that learns which process groups matter for each basin, transfers compatible observations between stages, and allocates a limited budget between feasible-region discovery and skill improvement. Group activation must be reversible: sparse initial screening can miss interactions, snow-dependent effects or routing controls. Compare adaptive groups against a fixed full-dimensional model and fixed existing stages.

An optional later fidelity hierarchy could use shorter training periods or coarser model representations to nominate candidates. Such evaluations are different models or targets; represent fidelity explicitly and verify rank correlation and admissibility across fidelities first. A shorter period must retain appropriate warm-up and representative wet/dry/snow years; reserve validation years throughout. All promoted candidates require the same full-fidelity verification. Do not assume low-fidelity ET or routing failures disappear at high fidelity, and do not infer parameter transfer across basins without a separately tested hierarchical model.

Asynchrony dispatches a new request when a worker becomes available, rather than waiting for the slowest request in a batch. It can improve utilization, but stale or duplicate suggestions can waste calls. For a GP acquisition use pending-candidate support or a documented fantasization scheme; the standard synchronous SCBO tutorial does not establish a complete asynchronous implementation. [Official BoTorch pending-point API](https://botorch.readthedocs.io/en/stable/acquisition.html). Each simulator worker needs a distinct TxtInOut copy and output directory, enforced receipts and atomic cache ownership. Cap workers according to measured memory, disk and CPU capacity.

## Fair experiment and adoption criterion

- Run paired DDS, constrained-GP and scrambled Sobol/random baselines on frozen basin projects. Include successful, near-miss, structurally poor and numerical-failure basins. Add RBF-DYCORS if the spanning design and compatibility checks pass.
- Use at least five paired seeds for a pilot and expand replication for inferential claims. Tune design settings on development basins; freeze them before unseen-basin testing. Reserve observation years before optimizer execution.
- Inspect budgets 30, 60 and 120 attempted full-fidelity search calls. Keep identical screening and verification budgets or charge differing screening explicitly. Present both total workflow and search-only curves.
- First compare all methods with one worker to isolate evaluation efficiency. Then compare a declared parallel strategy at 2 or 4 workers with the same total call budget and resource limit. Sequential DDS cannot become parallel by merely dispatching proposals that depend on an unevaluated incumbent; label any batch-DDS variant as a distinct algorithm.
- Report admissible best skill versus attempted engine calls; evaluations and wall time to first independently verified admissible solution; success rate; invalid-run rate; CPU-hours; orchestration/model-fit overhead; and paired basin/seed differences. Right-censor cases that never reach the target. Verification calls count in the headline cost.
- Show that a suggested method wins at relevant small budgets without systematically decreasing withheld-period performance or raising process violations. A speedup claim requires measured paired elapsed times, not dividing evaluation counts by worker number.

With `N` evaluations and `p` workers, an idealized execution lower bound is at least `max(sum(t_i)/p, max(t_i))`; scheduling, simulator contention, acquisition fitting and verification add time. Reducing `N` is an evaluation-saving claim; reducing idle time at fixed `N` is a parallel elapsed-time claim. Neither demonstrates improved scientific validity by itself.

## Existing surrogate and adversarial review

Code reviewed read-only at Builder commit `48f57fe1e65959d226cba3eafc6a001468276275`: `src/swatplus_builder/autoresearch/surrogate.py` and `src/swatplus_builder/calibration/forward.py`. The existing ensemble is bootstrap ordinary linear regression, not GP/RBF Bayesian optimization. Reusable components include typed requests, artifact extraction, fixed bootstrap seeds, model cards and an explicit basin-exclusion evaluation. It predicts one metric from raw parameter values; bootstrap spread is not a calibrated posterior or a probability that scientific constraints pass. Do not reuse its uncertainty threshold to replace real-engine observations in this benchmark.

Specific reuse safeguards: the default minimum is ten rows, independent of parameter dimension; with 14 parameters and an intercept this can be underdetermined even before a 20% row holdout and bootstrap duplication. `_fit_linear_regression` discards the rank returned by `lstsq`, has no normalization or regularization, and a shared linear bias can yield low ensemble spread even when predictions are wrong. `_rows_with_metric` checks presence rather than finiteness; the matrix-building functions do not explicitly reject non-finite inputs/targets. The inspected extractor does not select a common engine/input/window/objective context or call the nearby forward-artifact validation function. Store-level validation must still be checked; extraction alone does not establish scientific compatibility. Arbitrary cross-basin pooling provides no basin descriptors, so the same parameter vector cannot represent differing climate/geometry responses. A random row split can put highly related candidates from the same search in both folds; group by basin and frozen run context for transfer claims. Bounds/domain-distance, constraint residuals, failure categories and uncertainty-coverage assessment need explicit handling before scientific reuse.

The proposed experiment is defensible with the following corrections:

- **Make the budget arithmetic feasible first.** A total cap of 30 including full screening, design and verification may leave no optimization calls. Compute `search_remaining = cap - mandatory_screen - distinct_design - reserved_verification` for each arm/basin. Exact reusable screening points do not consume additional design calls, but rank-deficient or incompatible points cannot be counted as a usable RBF design. If there is insufficient budget, declare the arm infeasible at that cap rather than omitting required screening or verification. Keep the 30/60/120 total caps as requested; distinguish them from the earlier search-only exploratory suggestion in this note.
- **Freeze candidate acceptance as well as scalar utility.** GP constraint residuals and DDS feasibility must implement identical calibration-time policy. Otherwise a better acquisition method is confounded with a different feasible set. Exclude NaN/crash observations from numeric surrogate targets and retain their attempted-call cost. Do not fit a classifier on infrastructure outages.
- **Specify verification and observation holdout separately.** Full engine verification can rerun the selected vector without informing search. Withheld observation years should be evaluated once per predeclared final result, after development choices are frozen. If all three budgets are reported, freeze each budget's recommendation using training data and reveal their held-out results together; do not adapt later-budget search using the earlier-budget holdout score.
- **Avoid a contradictory endpoint.** Repeated independent held-out checks to establish “first verified solution” would violate the one-reveal holdout policy. For the first experiment report calls/time to first *training-period admissible* solution, then final independent verification and withheld performance. A verified time-to-target claim needs a separately preregistered verification schedule and its full cost, without feedback to optimization.
- **Do not treat paired seeds as identical search randomness.** Pair basin, starting state, common initial data and computational cap; preserve independent optimizer seed streams. Report per-basin paired differences and failure/censoring, not only an average dominated by easy basins. Five seeds are a pilot, not universal statistical sufficiency.
- **Keep a fallback baseline.** Include scrambled Sobol/random proposals or an explicitly declared exploration arm. If neither GP nor RBF outperforms simple space filling at these tiny budgets, do not interpret improvement over one DDS seed as proof of surrogate superiority. Any GP fitting failure or rank-deficient RBF fallback needs a declared policy and logged occurrence.

No implementation defect above has been reproduced with an engine run in this task; these are specific source-level reuse limitations. They do not justify altering the historical artifacts or weakening their claim gates.
