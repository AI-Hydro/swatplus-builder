# Independent implementation review

Date: 2026-10-02. Scope: the current experimental calibration foundation and proposed narrow live pilot. This review distinguishes code inspection, executed checks and future experiments. It does not certify faster calibration.

## Foundation findings

| Area | Assessment | Limit |
|---|---|---|
| Transformed objectives | New square-root/log NSE reject negative/non-finite values; constant observations are explicitly undefined. The opt-in policy binds exact training values and a frozen offset, and rejects missing selected metrics. | Context binds ordered observation values, not dates. An exact-output adapter must also seal dates, missing-data alignment, engine/input receipts and policy identity. |
| Typed evidence | Policy components are copied read-only after finite validation; constraint residuals and context are immutable. | A context supplied by a caller is an attestation, not independent proof that precomputed metrics used those observations and epsilon. |
| Historical objective | Existing log-KGE and historical scoring formula remain separate. New safeguards reject non-finite required NSE/KGE/PBIAS before candidate ranking. | Historical log-KGE remains unsuitable as a unit-independent new research objective. Its continued existence preserves replay and is not a scientific endorsement. |
| DDS cap | Opt-in hard search budgets include anchors and seed requests, with positive integer phase budgets and one seed. | This is a search request cap, not a whole-workflow engine cap. Screening, withheld scoring, fresh verification, previous attempts and failure retries need separate accounting. |
| Semantic cache | Cache identity now includes ordered observations/dates, staged static inputs, executable, scoring options, evaluator/parser/metric/gate sources and thread setting. Required cached metrics must be finite. Identical work paths are serialized within one process. | Inputs are assumed immutable after construction; locking is not cross-process. Telemetry counts engine-wrapper calls, which may fail before spawning the executable. |
| Constrained GP | Proposals are separate from measured results; only successfully measured candidates with all declared finite residuals <= 0 can be selected. Failed evaluations are not fitted as fake utilities. GP imports are checked before expensive callbacks. | A small single-region experimental challenger, not a complete SCBO reproduction. Numerical GP fitting may fail; report that failure without relabelling the arm as successful Bayesian optimization. |

The GP constructor initially accepted a fractional budget (for example 1.5), allowing two integer asks. This was reported to the implementation owner and the constructor now rejects fractions and booleans for proposal budget, initial design and candidate-pool size. Residual normalization must be explicit, especially when different constraint magnitudes determine the least-infeasible trust-region center.

Local verification performed by this reviewer: 36 objective-policy and existing metric tests pass; Ruff checks on owned objective files pass. These tests include unit conversion, zeros/constants, invalid inputs, context mismatch, no neutral fallback for undefined selected scores, immutable evidence and unchanged historical log-KGE counterexample. Other test and live results should be taken from their own retained artifacts rather than inferred from this review.

## Narrow pilot contract

The proposed development pilot uses the already inspected/calibrated USGS 12054000 model, keeps all other parameters fixed, varies only PET_CO and PERCO, and scores 2010–2015 after identical 2007–2009 initialization. It is a warm-started, touched two-dimensional integration experiment. It is not a cold-start reproduction of the 60/120-call screened protocol, independent temporal transfer experiment, new basin evaluation or model promotion.

If both arms receive six search requests including the same three initialization evaluations, each arm is attributed three initialization plus three new search evaluations. The shared initialization is physically acquired once: `3 shared + 3 DDS + 3 GP = 9` search engine calls. Reserving one fresh final training verification per arm gives **11 new physical attempted engine calls**, while the attributed per-arm total is **7 each / 14 combined**. Record physical and attributed counts separately. Prior smoke-test calls and historical calibration are additional development costs, not cold-start free evidence. Cache reuse, skipped verification after no admissible candidate, or failed attempts can change actual counts; reconcile telemetry rather than assume eleven successful solver executions.

Before running: freeze the complete pilot source/environment, observation alignment, input and executable identities, parameter bounds, utility weights, constraint definitions, shared initialization, seeds, timeout and both call reserves. Check GP dependencies first. Use independent invocation IDs for cached and fresh requests; a cache hit is not a fresh verification. Final selection uses only measured training-feasible utility and must not inspect withheld observations or adjust the experiment after seeing final outcomes.

A successful pilot demonstrates that these two search interfaces can obtain and independently reproduce exact training-period measurements under explicit budgets. With three adaptive proposals per arm on one previously calibrated model, it cannot support optimizer superiority, robust convergence, dimensionality reduction, generalization or a whole-pipeline speedup. Full cold-start and multi-basin/seed comparisons remain necessary.

## Pilot script review status

Reviewed `scripts/research/calibration_optimizer_pilot.py` after it became available. The current script implements the bounded shared-design accounting, durable pre-call reservations, isolated forced-fresh engine calls, copied-input identity, locked observation alignment check, training-only dates, exact parameter bounds, GP dependency preflight and complete loaded Python-source/dependency identity manifest. The experiment uses **raw KGE**, not the new transformed-NSE blend, to isolate interface and scheduling behaviour. Required NSE, KGE and PBIAS must all be finite, the process flag must be resolved, and exact measured volume/process residuals determine selection.

The initial script only recorded final fresh admissibility. Review requested a selected-search versus fresh metric comparison; the current script now compares NSE, KGE and PBIAS at `rel_tol=abs_tol=1e-10`, compares admissibility, retains fresh constraints and declares each arm `fresh_training_reproduced`, `verification_failed` or `not_reached`. An experiment's `completed` status describes execution, not model verification or promotion. Known engine/timeout exceptions are retained as failed attempts; unexpected adapter errors are journaled and re-raised rather than misrepresented as ordinary bad parameter candidates.

One nonblocking modelling caveat: the process constraint is a binary proxy for the unchanged existing gate, not a continuous measure of process error. At initial inspection a passing proxy was zero, placing it exactly on the GP feasibility boundary; that can waste proposals under posterior uncertainty even though measured selection remains correct. A declared negative passing margin preserves the binary gate semantics, but either representation is a heuristic that this tiny pilot cannot validate. Do not describe this as independently validated continuous hydrologic constraint learning.

Independent reviewer execution of the 12 offline pilot tests passes. They check eleven physical versus fourteen attributed calls, required finite observations, explicit infeasibility, fresh metric mismatch, charged timeout attempts, skipped final reruns when no admissible candidate exists, and propagation of unexpected adapter errors. Mocked GP proposals test integration/accounting, not the real posterior backend. Live outcomes and any experimental claims require their retained artifacts. No scientific blocker was found for the restricted development pilot once the final source is frozen; a larger comparative experiment remains necessary.

## Post-pilot interpretation and independent reconciliation

The frozen pilot completed in **187.886 s**. Independent reconstruction from `pilot_results.json` confirms each arm selected the largest measured raw KGE among its six declared admissible search records. DDS selected PET_CO = 1.182866230191236 and PERCO = 1.0; GP selected PET_CO = 1.191316128525054 and PERCO = 0.9974208631432864. Both remain inside the declared supported bounds.

The KGE gains over the already calibrated anchor are **0.000214316 for DDS** and **0.000070943 for GP**. DDS has the larger selected KGE in this particular run. Both selected models have slightly lower NSE and a slightly larger absolute PBIAS than the anchor. These small, objective-specific changes are not evidence of a substantive hydrologic improvement, statistical significance or superiority of either optimizer. The boundary/near-boundary PERCO selections also provide no evidence that this tiny design has established an interior optimum.

Independent search-versus-fresh comparison finds exact equality for every retained metric in each selected arm, including NSE, KGE, PBIAS and reported gates. Both fresh models satisfy the declared volume residual and process proxy. Eleven distinct invocation receipts report completion, cache misses and engine-wrapper calls; all eleven physical callback records are successful. Their identities reconcile with three shared initialization runs, three DDS proposals, three GP proposals and two fresh final reruns. Each arm has six attributed search evaluations plus one verification, giving fourteen attributed calls and eleven actual callbacks. The callback duration sum is 186.506 s; the remaining approximately 1.38 s of whole-pilot elapsed time covers surrounding work. This accounting confirms the bounded execution and fresh training reproducibility; it does not quantify cold-start or historical development cost savings.

Every measured candidate passed the declared volume/process constraints, so this run does **not** exercise learning of an infeasible hydrologic region. Some low-skill search candidates have `physical_gate_passed = 0` while their explicit calibration process gate passes. That follows the predeclared separation of skill diagnostics from candidate process restrictions; it must not be summarized as every candidate passing all diagnostic gates. The selected/fresh models pass both reported flags. A signed categorical process pass is still not proof of complete water-balance closure or independent process validation.

The defensible result is a successful integration and exact fresh-training reproduction of two bounded search interfaces on a touched two-parameter development model. No withheld data were consulted or scored in this pilot. An independent claim about generalization, reduced solver calls, convergence, constrained learning or calibration speed still requires the previously specified frozen, multi-basin, multi-seed comparison, including screening and verification costs. Historical log-KGE diagnostics were retained but were not used to rank these candidates; their known unit dependence remains a reason to keep them out of a new objective. No post-result tuning or additional engine runs were performed by this reviewer.

A retention limitation was reported by the run owner: GP numerical jitter warnings appeared in tool stdout, but the console stream was not saved with the experiment. This reviewer has not independently inspected those warnings. The completed proposal methods and exact solver measurements remain retained, but the next frozen comparison should capture stdout/stderr and warning records so numerical stabilization and fit diagnostics can be audited. Do not retrospectively infer posterior reliability from successful callback execution.
